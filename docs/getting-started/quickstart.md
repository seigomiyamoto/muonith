# Quick Start

This guide starts with the primitive-shape demos and then shows the bundled
`tutorial` station.

!!! note "Prerequisites"
    Make sure you have completed the [Installation](installation.md) steps
    and have a release build available (`bash brelease.sh`).
    Visualization scripts also require
    [Python packages](installation.md#python-packages-optional).

## Primitive-shape demos

Two basic shape demos reuse the `tutorial` detector layout and generate their
DEM at run time. They are useful for confirming that the pipeline works on
simple known geometry before moving to a fuller synthetic volcano.

For the flat-topped cylinder demo:

```bash
bash setup_station.sh eg-cylinder
cd work/eg-cylinder/swp001/
bash run_prg.sh true 42
```

For the square-pyramid demo:

```bash
bash setup_station.sh eg-square-pyramid
cd work/eg-square-pyramid/swp001/
bash run_prg.sh true 42
```

Both demos write the generated DEM under `work/<station>/dem/` and the figures
under `work/<station>/swp001/figs/`. See
[Synthetic DEM Examples](../user-guide/synthetic-dem-examples.md) for the
shape definitions and expected outputs.

## Tutorial station

The default runnable sample is `tutorial`, a fully synthetic station that ships
without GSI (Geospatial Information Authority of Japan) survey data. Its DEM,
detector layout, and parameter file are all bundled with the repository, so it
is the recommended first run.

The bundled inputs include:

- **DEM** (Digital Elevation Model): `data/tutorial/tutorial-5m.g2zbin`
- **Detector parameters**: 11 detector runcards under
  `data/tutorial/detparams/0.2m2_120days/`
- **Station config**: `param_sites/tutorial.json5`
- **Muon flux tables**: Pre-computed Daemon-Groom flux model under
  `fluxtable/daemon_groom/`

`tutorial` uses a local meter coordinate system, so `param_sites/tutorial.json5`
sets `"skip_detparams": true`. This means `setup_station.sh` reuses the bundled
detector runcards instead of regenerating them from KML or GeoJSON.

## Generate the working directory

From the repository root, run:

```bash
bash setup_station.sh tutorial --run
```

This checks the local environment, prepares `.venv/` if needed, links the
DEM from `data/tutorial/`, reuses the detector runcards, and creates or updates
the working files under `work/tutorial/`. Existing generated files are skipped
unless you pass `--force`.

After generation, the standard reconstruction run is:

```bash
cd work/tutorial/swp001/
bash run_prg.sh true 42
```

The arguments mean:

| Argument | Meaning |
|---|---|
| `true` | Run the C++ executable before plotting |
| `42` | Random seed for reproducible Poisson draws |

To regenerate figures from existing output without rerunning the executable:

```bash
bash run_prg.sh false
```

## What the run does

The standard `tutorial` run executes the 3D reconstruction pipeline:

| Module | Step |
|---|---|
| 1 | Load parameters and initialize |
| 2 | Build detector array |
| 3 | Build geometry from the DEM and voxel grid |
| 4 | Compute ray-tracing path lengths |
| 5 | Compute prior density-length |
| 6 | Compute expected muon counts |
| 7 | Run linear inversion |

`param_sites/tutorial.json5` currently sets the default `swp001` run to stop
after Invert Density (Module 7). Full Analyze Errors (Module 8) error analysis can be enabled through the
`end_stage` and `module8_mode` settings described in the
[Pipeline](../user-guide/pipeline.md) and [Output](../user-guide/output.md)
pages.

## Check the output

After the command finishes, inspect:

| Path | What to check |
|---|---|
| `logs/time_report.log` | Runtime and peak memory report from `/usr/bin/time` |
| `logs/error_auto_plot.log` | Plotting errors, if any |
| `tmp/` | Intermediate matrices, reconstructed density, and cross-section data |
| `figs/` | Generated detector, signal, and reconstruction figures |

For additional context about the bundled synthetic station, see
[Synthetic DEM Examples](../user-guide/synthetic-dem-examples.md).

## Other bundled stations

Other station presets are available under `data/` and `param_sites/` and can
be used as starting points for custom configurations:

| Station | Description |
|---------|-------------|
| `eg-cylinder` | Primitive flat-topped cylinder demo. DEM is generated by `run_prg.sh`, JSON5 at `param_sites/eg-cylinder.json5` |
| `eg-square-pyramid` | Primitive square-pyramid demo. DEM is generated by `run_prg.sh`, JSON5 at `param_sites/eg-square-pyramid.json5` |
| `tutorial` | License-free synthetic omuro-scale volcano (no GSI data). DEM at `data/tutorial/tutorial-5m.g2zbin`, JSON5 at `param_sites/tutorial.json5` |
| `omuro` | Mount Omuro reference configuration. DEM at `data/omuro/omuro-5m_cut.g2zbin`, JSON5 at `param_sites/omuro.json5` |
| `tarumae-dome` | Tarumae lava dome (Hokkaido). KML at `data/tarumae/tarumae-dome.kml`, JSON5 at `param_sites/tarumae-dome.json5` |
| `tarumae-mid01` | Tarumae mid-flank site. KML at `data/tarumae/tarumae-mid01.kml`, JSON5 at `param_sites/tarumae-mid01.json5` |

To create a new station, start from:

```bash
bash setup_station.sh <station_name>
```

Then edit `param_sites/<station_name>.json5`, place DEM and detector input
files under `data/<station_name>/`, and run:

```bash
bash setup_station.sh <station_name> --run
```

See [Utility Scripts -- init_work_site.py](../reference/scripts.md#init_work_sitepy)
and [Utility Scripts](../reference/scripts.md) for details.

## Showa case studies

Showa-shinzan examples are useful as case studies for detection-limit plots
and synthetic 3D reconstruction figures, but they are not the default first
run. Treat `work/showa/depth003/` and `work/showa/rec001/` as advanced
reference cases until the Showa setup is reproducible through
`data/showa/`, `param_sites/showa.json5`, and `setup_station.sh`.

For the underlying concepts and figures, see:

- [Depth vs. Spatial Resolution](../concepts/depth-resolution.md)
- [Output](../user-guide/output.md#showa-shinzan-reference-reconstruction)
